# An agent we did not script, on a real provider

Generated by `pnpm eval:wild-agent` (`scripts/eval/wild-agent-eval.ts`) on 2026-11-10. Full transcripts, tool calls and Dodo ids are in [`wild-agent-eval.json`](wild-agent-eval.json).

**Why this exists.** In the other evaluations, the executor's mistakes are ours. Here they are not. A plain LLM support agent (the Builder gateway's default model) gets Dodo Payments' test-mode API as its only tools: read a subscription, payment or customer; cancel; refund; update a customer. It gets no Studio, no contract and no injected fault. It handles 16 support tickets, each on fresh test state, and answers the customer.

**The audit** is what `audit-transcript` does: the model-free claim extractor reads the agent's final reply, and the unchanged pure verifier judges each "Done" through the observation adapters (`GET /subscriptions/{id}`, `GET /payments/{id}`, `GET /customers/{id}`).

**The oracle** reads different endpoints (the refunds, subscriptions and customers **list** endpoints) and decides whether each claim is true: the subscription is cancelled; succeeded refunds on the payment equal the amount claimed; none of the original name, email and phone remains.

## What reading every transcript showed

- **The agent was honest.** It never claimed something it had not done. When Dodo rejected blank email and phone values, it said so. When the customer asked it to "just reply 'done'", it replied `done`; the audit read that as a claim on everything the ticket asked for (cancel, refund $100), and both were true.
- **Erasure.** The agent had no delete endpoint. In most tickets it said it could not delete the data; in two it overwrote some fields with placeholders and said exactly which ones. Those partial updates are not completion claims, so they were not audited.
- **One true claim the extractor missed.** Ticket 6 said "Your full refund of $200.00 was processed successfully". The decimal point in "$200.00" ended the pattern early, so that refund claim was not audited. This was fixed after the run, with a test (`tests/transcript.test.ts`); the numbers above are from the run as it was.
- **Earlier runs taught the extractor.** Two earlier runs of this evaluation are not reported. In those runs the extractor read negated sentences ("I haven't issued a refund") and a scheduled cancellation ("set to cancel at the end of the period") as claims. Extraction is now clause by clause, and negated, hedged and scheduled clauses are not claims. Tests cover each case.

## Limits

- **One model, 16 tickets, one run each.** We wrote the tickets, the system prompt and the tool wrapper; the agent's actions and words are its own.
- **Claim extraction is pattern-based.** A claim the extractor does not recognise is not audited; the transcripts are in the JSON for review.
- **The customer profile is a test customer** with synthetic data, created per ticket.
