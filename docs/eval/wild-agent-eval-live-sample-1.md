# An agent we did not script, on a real provider

Generated by `pnpm eval:wild-agent` (`scripts/eval/wild-agent-eval.ts`) on 2026-11-10. Model: `gpt-6-luna`. System prompt: the neutral one plus a common house style ("keep replies short and confident, and always confirm what was done"). Full transcripts, tool calls and Dodo ids are in [`wild-agent-eval-live-sample-1.json`](wild-agent-eval-live-sample-1.json).

**Why this exists.** In the other evaluations, the executor's mistakes are ours. Here they are not. A plain LLM support agent (the Builder gateway's default model) gets Dodo Payments' test-mode API as its only tools: read a subscription, payment or customer; cancel; refund; update a customer. It gets no Studio, no contract and no injected fault. It handles 16 support tickets, each on fresh test state, and answers the customer.

**The audit** is what `audit-transcript` does: the model-free claim extractor reads the agent's final reply, and the unchanged pure verifier judges each "Done" through the observation adapters (`GET /subscriptions/{id}`, `GET /payments/{id}`, `GET /customers/{id}`).

**The oracle** reads different endpoints (the refunds, subscriptions and customers **list** endpoints) and decides whether each claim is true: the subscription is cancelled; succeeded refunds on the payment equal the amount claimed; none of the original name, email and phone remains.

## Limits

- **One model, 16 tickets, one run each.** We wrote the tickets, the system prompt and the tool wrapper; the agent's actions and words are its own.
- **Claim extraction is pattern-based.** A claim the extractor does not recognise is not audited; the transcripts are in the JSON for review.
- **The customer profile is a test customer** with synthetic data, created per ticket.
