Agents make promises.
This is where they get checked.

An AI support agent tells a customer “Done: cancelled, refunded $100, your data is deleted.” Trust Contract Studio doesn’t take its word. It checks every “Done” against the provider’s own records and answers VERIFIED, FAILED or UNKNOWN, with the evidence.

What it does

Audit any agent. Run work under a contract. Keep watching.

Audit a transcript

Paste any agent’s transcript. Its “Done” claims become clauses that a pure verifier checks at the providers. Nothing is executed.

Run under a contract

A request becomes promises with a definition of done. A person approves, bound to a hash of the exact terms; the agent can’t. Repairs come from the evidence.

Keep watching

A scheduled automation re-checks kept promises. If a refund changes at Dodo later, the promise turns FAILED and an event fires.

Built on Agent-Native

The safety rules are framework gates, not prompts.

  • Every capability is one defineAction() shared by the UI, the in-app agent and external agents over MCP.
  • Approval is uiOnly: agents and MCP clients never get it. An external agent that tries gets “Unknown tool”.
  • A chat renderer puts a seal on every “Done”: what the agent says, next to what the verifier checked.
  • The watch is a framework event (tcs.verdict.changed) plus an automation the agent creates with manage-automations.
  • 98 unit and integration tests, 9 Playwright tests including an axe-core audit and a keyboard-only run.
